# 실습 1 실패 사례 분석

- 작성일: 2026-10-12
- 대상: `get_inventory` 도구 정의 개선
- 상태: 교재 사례에 대한 문서 분석. 실제 모델 실험·실행 로그가 아님.
- 결과물: [도구 정의서](tool-definition.md)

## 교재 원문과 분석의 구분

아래 실패 행동과 보완 문장은 교재 §3 표에 있는 사례다. 사용자 요청의 정확한 문구·모델·실행 로그는 표에 없으므로 만들어 기록하지 않는다. 기대 행동은 이 사례를 바탕으로 정리한 문서상 판정 기준이다.

## 사례 1. 존재하지 않는 창고와 반복 호출

- 교재 실패: 존재하지 않는 창고 코드를 임의로 넣어 같은 오류를 반복 호출했다.
- 교재의 빈 항목: 스키마, 실패 뒤 행동.
- 교재 보완: 허용되지 않은 창고면 허용 코드를 물어야 하고 재호출하지 않는다.
- 분석: 입력의 허용 범위와 오류 뒤 멈춤 규칙이 부족했다. 재시도해도 같은 잘못된 코드가 유효해지지 않는다.
- 개선 전 문제: 창고가 불명확해도 모델이 코드를 추측할 수 있고, 실패하면 그대로 반복할 수 있다.
- 개선 후: warehouse_id를 SEOUL-01·BUSAN-02로 제한하고, 확정되지 않았으면 먼저 질문한다. WAREHOUSE_NOT_ALLOWED 뒤 같은 인자로 재호출하지 않는다.
- 올바른 다음 행동: 사용자가 의도한 허용 창고를 확인한다. 수정된 유효 인자로 조회하는 것은 가능하지만 이전 오류의 무조건 재시도와 구분한다.
- 대응: 도구 정의서 §3·4·6.

## 사례 2. SKU 없이 유사 상품을 임의로 선택

- 교재 실패: SKU를 모른 채 가장 비슷한 상품을 골라 조회했다.
- 교재의 빈 항목: 인자 스키마, 실패 뒤 행동.
- 교재 보완: SKU는 필수이며 없으면 상품 식별자를 물어야 한다.
- 분석: 비슷한 상품과 같은 상품은 다르다. 사용자가 의도한 상품이 아닌 결과를 정확한 답변처럼 제시할 수 있다.
- 개선 전 문제: 입력 누락을 모델의 추측으로 채운다.
- 개선 후: sku를 필수 문자열 3~32자로 정의하고, 누락·모호함·INVALID_SKU이면 정확한 식별자를 질문한다. 유사 상품으로 대체하지 않는다.
- 올바른 다음 행동: 상품 코드를 질문하고, 확인될 때까지 조회하지 않는다.
- 대응: 도구 정의서 §3·4·6.
- 한계: 교재 §5 함수는 상품 존재 여부를 검사하지 않고 INVALID_SKU를 반환하지 않는다. 문서 규칙과 예제 구현의 차이이며 아직 수정하지 않았다.

## 사례 3. 내부 원가를 최종 답변에 노출

- 교재 실패: 응답의 내부 원가를 최종 답에 인용했다.
- 교재의 빈 항목: 반환 형식.
- 교재 보완: 가용 수량과 확인 시각만 근거로 쓴다.
- 분석: 도구가 반환한 모든 정보가 사용자에게 공개해도 되는 정보인 것은 아니다.
- 개선 전 문제: 정의되지 않은 필드까지 답변 근거로 사용한다.
- 개선 후: 수량과 시점의 근거를 available_quantity와 checked_at으로 제한하고 내부 원가·추가 필드를 인용하지 않는다. SKU·창고는 요청과 결과 일치 확인에 사용한다.
- 올바른 다음 행동: 조회 수량과 그 확인 시점을 근거로 재고 질문에 답한다. 원가·가격·이익을 추정하지 않는다.
- 대응: 도구 정의서 §5.
- 실행 계층 요구: 모델에 결과를 전달하기 전에 허용 필드만 전달하도록 제한해야 한다. 문서상 금지만으로 안전을 보장하지 않는다.

## 사용자 확인으로 확정한 선택

교재는 오류별 재시도·질문·중단의 세부 대응을 모두 지정하지 않는다. 사용자가 다음 안을 선택했다.

> 시간 초과·일시적 연결 실패만 한 번 재시도하고, 다시 실패하면 중단.

이는 읽기 전용 조회의 일시적 실패를 복구할 기회를 주되 반복 호출을 제한하는 설계다. 상품·창고 입력 오류, 권한 오류, 결과 불일치에는 적용하지 않는다. 실제 통신 오류를 발생시키거나 재시도를 실행한 것은 아니다.

## 문서상 검토 결과

| 점검 | 정의서의 대응 | 판정 범위 |
|---|---|---|
| 허용되지 않은 창고를 임의 선택하지 않음 | enum·확인 질문·오류 뒤 반복 금지 | 문서 규칙 확인 |
| SKU 누락을 유사 상품으로 채우지 않음 | 필수 입력·길이·정확한 식별자 질문 | 문서 규칙 확인 |
| 내부 원가를 인용하지 않음 | 답변 근거 제한·실행 계층 필드 제한 요구 | 문서 규칙 확인 |
| 통신 오류가 무한 반복되지 않음 | 추가 재시도 최대 한 번, 다시 실패하면 중단 | 사용자 선택 반영 |
| 조회 오류를 수량 0으로 바꾸지 않음 | 성공과 오류 구분 | 보완 규칙 확인 |

문서에 대응 규칙이 존재한다는 점만 확인했다. 모델이 실제로 이를 지킨다는 판정은 실습 2의 실행 기록으로 해야 한다.
