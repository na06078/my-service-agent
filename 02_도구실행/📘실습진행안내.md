# 실습 2 진행 안내

## 현재까지 확인한 것

- LLM: 기존 llama-server `b11429-d81235049`의 `Qwen 3.8 27B`.
- 교재의 Ollama 연결을 OpenAI 호환 API와 `ChatOpenAI`로 변경했다. 모델 차이 때문에 교재와 동일 출력이 보장되지는 않는다.
- 재고 함수는 교재 기준이다. 실제 창고가 아니라 수량 7과 고정 시각을 반환하는 모의 함수다.
- 모델은 실제로 호출했고, 함수도 실제로 실행했다. 결과를 만들어 붙인 것이 아니다.
- 실행 기록은 `실행기록/`의 TXT(읽기용)와 JSON(전체 모델 응답·조건) 쌍에 저장한다. 새 실행은 새 번호로 저장한다.

## 실행 방법

Windows PowerShell에서 이 문서가 있는 `02_도구실행` 폴더를 열고 실행한다. 기존 llama-server가 켜져 있어야 한다.

```powershell
# 정상 요청
.\.venv\Scripts\python.exe .\inventory_tool.py

# 교재의 경계 요청
.\.venv\Scripts\python.exe .\inventory_tool.py --prompt "부산 3번 창고의 A-17 재고를 알려 줘"

# 같은 요청, 실습 1의 사용 조건·실패 대응을 설명에 추가
.\.venv\Scripts\python.exe .\inventory_tool.py --prompt "부산 3번 창고의 A-17 재고를 알려 줘" --description definition

# 모델 호출 없는 코드 검사
.\.venv\Scripts\python.exe .\테스트_재고도구.py
```

`definition`은 `01_도구정의/tool-definition.md`의 사용 조건·실패 대응을 읽어 도구 설명에 추가한다. 입력 스키마나 함수 자체를 강화하는 모드가 아니다. 비교 실행은 질문·함수·온도를 유지하고 설명만 바꿨다.

## 실제 실행 결과

확인일: 2026-10-12. 온도 0, 출력 한도 1024, `enable_thinking: false`를 요청했다. 모든 기록에 서버 빌드·모델 경로·라이브러리 버전·실제 응답을 남겼다.

| 기록 | 조건 | 실제 관찰 | 판정 |
|---|---|---|---|
| 실행기록-01 | 정상 요청, 교재의 두 번째 메시지 구성 | 정확한 호출과 함수 결과까지 성공. 최종 요청에서 HTTP 500 `No user query found in messages.` | Qwen 템플릿에 최초 사용자 질문이 필요한데 교재가 빠뜨림 |
| 실행기록-02 | 최초 질문을 결과 재입력에도 보존 | `get_inventory(A-17, BUSAN-02)` 실행 후 7개라고 답함 | 한 바퀴 동작 확인. 실제 재고 검증은 아님 |
| 실행기록-03 | 교재 설명 + 부산 3번 요청 | 모델이 `BUSAN-02`로 임의 변경해서 호출하고 7개라고 답함 | 실행은 끝났지만 사용자 의도를 바꾼 경계 처리 실패 |
| 실행기록-04 | 같은 질문 + 실습 1 설명 | 모델이 호출하지 않고 의도한 창고를 확인함. 이후 코드가 `IndexError` | 모델의 확인 질문은 기대 행동. 호출을 가정한 교재 하네스는 실패 |

실행기록-02의 답변에도 “현재 가용 재고”라는 표현이 있다. 고정된 2026-08-27 시각의 모의 값을 최신 실제 재고로 받아들이면 안 된다. 반환 근거와 답변의 표현은 따로 평가한다.

## 교재와 달라진 것·그대로인 것

- 연결: `ChatOllama` 대신 `ChatOpenAI`로 현재 llama-server에 요청.
- 모델: 교재 `qwen3.5:2b` 대신 사용자가 지정한 Qwen 3.8 27B.
- 호환 수정: 두 번째 모델 입력을 사용자 질문 → assistant 호출 요청 → ToolMessage 순서로 구성. 원래 누락으로 발생한 오류는 실행기록-01에 보존.
- 기록 보강: 최종 답변을 120자로 자르지 않고 전체 기록. 오류도 숨기지 않음.
- 함수는 그대로: 승인 창고 검사만 수행. SKU 3~32자·상품 존재·INVALID_SKU 반환·인증은 구현하지 않음.
- 도구 미호출 때의 IndexError는 교재 관찰 항목으로 보존. 운영용의 안전한 중단 처리는 후속 개선이며 현재 구현했다고 주장하지 않음.
- 첫 호출만 실행하고 결과 재입력 1회로 종료. 자동 다중 턴 에이전트가 아님.
- 일시적 통신 오류 재시도 계약은 실습 1의 설계이며 이번 교재 코드에는 구현하지 않았다.

## 사용자님이 해 볼 부분

1. 정상 요청에서 `[1]` 호출 인자, `[2]` 함수 반환, `[3]` 답변을 구분한다.
2. 같은 “부산 3번” 질문에서 교재 설명과 보완 설명의 호출 여부를 비교한다.
3. 관찰을 한두 문장으로 적는다. 어시스턴트의 해석이 아니라 사용자님이 이해한 내용을 남긴다.
4. 다음에는 질문 또는 설명 한 가지만 바꿔 본다. 새 결과는 기존 파일을 덮어쓰지 않는다.

사용자 직접 실행·관찰은 아직 미확인이다. 어시스턴트의 자동 실호출과 구분한다.
