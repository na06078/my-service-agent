# Qdrant MCP 검색 연결 안내

## 현재 검증 상태

- 날짜: 2026-10-12.
- `mcp-server-qdrant 0.8.1`, `FastEmbed 0.9.0`, `ONNX Runtime 1.31.0`을 프로젝트 전용 Python 3.11 환경에 설치했다.
- 기존 `.safetensors`는 보존. FastEmbed 지정 `Qdrant/bge-small-en-v1.5-onnx-Q`의 ONNX판을 `임베딩모델/`에 다운로드했다.
- `model_optimized.onnx` 66465124바이트. 실제 문장을 임베딩해 384차원 벡터 생성 확인. 해시·필수 파일은 `임베딩_검증결과.json` 참조.
- 리랭커 미사용. Hindsight 서버·DB·설정 변경 없음.
- SDK로 실제 MCP 초기화·도구 목록·문장 3개 저장·검색 확인 PASS. `실행기록/MCP검증-01.json`과 서버 로그 참조.
- 위 SDK 검사는 LLM이 선택한 실험이 아니다. 이후 사용자가 웹 채팅의 저장·검색 호출과 결과·최종 답변을 공유하여 네이티브 흐름도 확인했다. 아래 사용자 실습 결과 참조.
- 사용자가 실습 BAT로 서버를 다시 켰다고 알렸다. /health HTTP 200, Qwen 3.8 27B, /tools HTTP 200에서 qdrant_qdrant-store·qdrant_qdrant-find 등록 확인. 확인 과정에서는 문장 저장·검색이나 모델 질문을 보내지 않았다.

## 교재 설정과 설치 패키지의 차이

교재의 환경변수 이름 일부가 설치한 공식 패키지의 실제 설정 이름과 다르다. 교재 값을 그대로 넣으면 모델·컬렉션 설정이 적용되지 않을 수 있다. 설치 패키지 `mcp_server_qdrant/settings.py`의 validation_alias를 확인해 다음과 같이 맞췄다.

| 교재 이름 | 실제 적용한 이름 | 값 |
|---|---|---|
| QDRANT_URL | QDRANT_URL | :memory: |
| QDRANT_COLLECTION | COLLECTION_NAME | policies |
| EMBEDDER_PROVIDER | EMBEDDING_PROVIDER | fastembed |
| FASTEMBED_MODEL | EMBEDDING_MODEL | BAAI/bge-small-en-v1.5 |

추가 설정 `FASTEMBED_CACHE_PATH`로 이 폴더의 모델 위치를 지정하고 `HF_HUB_OFFLINE=1`로 MCP 실행 중 모델을 새로 받지 않도록 했다. 준비 다운로드는 별도 승인 범위에서 완료했다. 정책 문장만 사용하는 실습이며 민감정보를 넣지 않는다.

## 실제 MCP 프로토콜 검증

PowerShell에서 이 `03_검색연결` 폴더를 열고 실행한다.

```powershell
..\02_도구실행\.venv\Scripts\python.exe .\검증_MCP_저장검색.py
```

MCP 서버를 자식 프로세스로 열고 같은 연결 안에서 저장·검색한 뒤 정상 종료한다. 사용자 LLM은 호출하지 않는다. 종료하면 메모리 컬렉션은 사라진다.

실제로 확인한 도구는 `qdrant-store`, `qdrant-find`다. 저장 문장은 다음과 같다.

1. 환불은 구매 후 7일 이내에 가능하다.
2. 배송은 영업일 기준 2일이 걸린다.
3. 회원 등급은 매월 1일에 갱신된다.

검색 “환불 기한이 어떻게 돼?”는 위 문장을 환불 → 배송 → 회원 순서로 반환했다. 문장 세 개짜리 예제의 동작 확인이지 한국어 검색 품질 전반의 평가가 아니다.

## llama-server에 등록할 설정

설정 파일은 `검색연결설정.json`이다. 교재의 MCP 서버를 llama-server가 직접 실행하도록 Cursor 호환 형태로 작성했다. 별도의 OpenCode·Claude Code는 사용하지 않는다. 프로젝트 전용 Python으로 설치한 패키지를 실행하므로 전역 uvx 환경에 의존하지 않는다.

종료 전 서버: `C:\llm\llama-b11429-bin-win-vulkan-x64\llama-server.exe`, PID 25480, `http://127.0.0.1:8080`. 재실행 후 PID는 다시 확인해야 한다.

종료 전 서버에는 MCP 설정이 없었고, 현재 실습 BAT에는 다음 항목을 추가했다. 기존 모델·GPU·MTP·컨텍스트·샘플링 옵션은 유지했다.

```text
--mcp-servers-config "C:\my vault\ME\1. Note\Hermes\Aiffel_Work\02_노드실습\MCP_도구활용_실습\03_검색연결\검색연결설정.json"
```

`--agent`나 `--tools all`은 추가하지 않는다. 이 실습에는 파일 수정·명령 실행 도구가 필요 없다. MCP CORS 프록시도 stdio 네이티브 연결에 필요한 옵션이 아니다.

사용자가 기존 서버를 직접 종료했다. 기존 실행기 설정은 변경하지 않고 이 폴더의 `라마서버_실습실행.bat`를 사용자가 실행하도록 승인했다. BAT와 동반 `라마서버_실습실행.ps1` 작성 완료.

### 지금 실행할 파일

1. `라마서버_실습실행.bat`를 더블클릭한다.
2. 열린 콘솔에서 모델 로드가 끝날 때까지 기다린다. 이 창을 계속 열어 둔다.
3. 브라우저에서 `http://127.0.0.1:8080`을 연다. 기존 실행기를 동시에 실행하지 않는다.

실행 파일은 종료 전 모델·GPU·MTP·컨텍스트·샘플링 인자의 값·순서를 보존하고 MCP 설정만 추가했다. 실제 출력 인자를 기존 인자 57개 토큰과 대조하여 일치 PASS. 읽기 전용 `-CheckOnly` 모드로 BAT 실행 성공, 서버 시작·프로세스 종료 없음 확인. 이 점검은 실제 모델 로드 성공을 뜻하지 않는다.

스크립트는 다른 프로세스를 중지하지 않으며 포트 8080이 사용 중이면 실행을 중단한다. 서버 로그는 `실행기록/서버로그-날짜-시각.txt`에 생성한다. 최초 질문의 교재 호환 수정과는 별개로 서버의 기본 샘플링 설정은 그대로다.

해당 빌드의 `server-mcp.cpp`에서 실제 호출용 프로세스 재사용을 확인했고, 이후 사용자 공유 출력에서 네이티브 저장→검색 반환도 확인했다. 프로세스 종료·재시작 시 `:memory:` 데이터는 사라진다.

## 재시작 후 사용자 실습

llama-server 웹 채팅에서 다음을 입력한다.

> 다음 세 문장을 저장해 줘: “환불은 구매 후 7일 이내에 가능하다.” “배송은 영업일 기준 2일이 걸린다.” “회원 등급은 매월 1일에 갱신된다.” 그리고 “환불 기한이 어떻게 돼?”와 비슷한 문장을 찾아 줘.

확인할 것:

- 모델이 저장·검색 도구를 실제로 요청하는가?
- 각 호출 인자는 무엇인가?
- 검색 결과를 받은 뒤 7일이라는 근거로 답하는가?
- 서버가 추가한 이름 접두사(`qdrant_...`)와 원래 MCP 이름을 구분한다.

### 사용자 순차 실습 결과

- 저장: 각 문장을 information에 넣어 qdrant_qdrant-store 호출, 모두 Remembered ... in collection policies 반환. `실행기록/사용자저장-01.json` 참조.
- 검색: 대화 기록 속 문장만 보고 답하는 영향을 줄이려 새 채팅을 안내했다. 기존 같은 채팅 안내는 검증 목적에 덜 적절해 정정. 서버는 유지하고 이전 문장은 다시 넣지 않도록 안내. 브라우저 세션 분리는 직접 관찰하지 않음.
- 실제 qdrant_qdrant-find(query="환불 기한")가 저장 문장 3개를 반환했고 환불 문장이 첫 결과. 공유 출력에 새 저장 호출 없음. `실행기록/사용자검색-01.json` 참조.
- 핵심 답변 “구매 후 7일 이내”는 검색 근거와 일치. 추가한 “그 이후에는 환불이 불가능”은 원문에 없어서 답변 충실도 일부 미달.
- 더 충실한 답변: “저장된 안내에 따르면 환불은 구매 후 7일 이내에 가능합니다. 7일 이후 처리나 예외 조건은 제공된 자료에 없습니다.”
- 저장→검색→모델 답변 흐름은 확인했으나 모든 답변이 올바르거나 일반 검색 품질이 검증된 것은 아님. 추가 개선·재실험은 자동으로 진행하지 않는다.
